Architecture

ELO Payroll Association — CRM

1. Overview

This is a Next.js (App Router) app deployed on Vercel, backed by a Supabase Postgres database, with Resend for email. It has two surfaces: a public marketing site that captures leads, and an /admin CRM. /admin starts open and gets locked down with Supabase Auth later in the build.

2. How the pieces fit

Next.js (App Router)

Renders the public site and /admin. Server code handles form submissions and all database reads and writes — the browser never talks to the database directly.

Vercel

Hosts and deploys the app. Environment variables hold every secret. A push deploys.

Supabase (Postgres)

The database. Accessed server-side only, using the service key. Secrets never reach the browser.

Resend

Sends the confirmation email when a lead comes in (wired in Build 2).

Environment variables

  • NEXT_PUBLIC_SUPABASE_URL — the address of the Supabase project.
  • NEXT_PUBLIC_SUPABASE_ANON_KEY — the public client key, safe for the browser.
  • SUPABASE_SERVICE_ROLE_KEY — the private server key for all reads/writes; never exposed to the client.
  • RESEND_API_KEY — authorizes sending confirmation emails.
  • NEXT_PUBLIC_SITE_URL — the live domain, used for email links and redirects.

3. The lead flow

  • A visitor submits the contact form on the public site.
  • Server upserts a People row by email — an existing person is updated, never duplicated.
  • Server creates a linked Contacts row in status new_lead.
  • (Build 2) Resend sends a confirmation email to the visitor.
  • The operator sees the lead in /admin and works it through the pipeline.
  • Each status change writes one activity_log row, so nothing is ever lost track of.
